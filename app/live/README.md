# PeMS station to MQTT

Selected station: **PeMS mainline VDS 1108617, Old Town Ave/Moore to 5 NB**, I-5 northbound, District 11, San Diego, CA postmile 19.216. [PeMS 5-minute station report](https://pems.dot.ca.gov/?station_id=1108617&dnode=VDS&content=loops) requires sign-in. The matching [CWWP2 camera C009 image](https://cwwp2.dot.ca.gov/data/d11/cctv/image/c009i5justnorthofoldtown/c009i5justnorthofoldtown.jpg), “I-5 : Just North Of Old Town,” faces north at postmile 19.210, only 0.006 mile from the detector. The [official camera catalog](https://cwwp2.dot.ca.gov/data/d11/cctv/cctvStatusD11.json) lists it as in service.

On 2026-11-13, PeMS showed **100% observed** for Nov 7–12 (Nov 6: 96.88%; Nov 3: 98.61%). Its 5-minute table had a fresh 06:15 PST row with aggregate **298 vehicles/5 min, 45.7 mph, 6.8% occupancy, 4 lane points, 100% observed**. The camera image showed actual traffic and carried a 06:21:17 PST timestamp. These are point-in-time checks; monitor continued freshness and observed percentage during operation. Oso Parkway VDS 1204515 was rejected after its observed percentage fell to 0% for Nov 7–11, despite its working camera.

PeMS [documents an official real-time FTP feed](https://pems.dot.ca.gov/?directory=Help&dnode=Help&content=var_intro) with 5-minute processed files. Its [format page](https://pems.dot.ca.gov/?directory=Help&dnode=Help&content=var_fmt) specifies `D11/Data/5min/5minagg_YYYYMMDDHHMMSS.txt.gz` and the columns `VDS_ID,FLOW,OCCUPANCY,SPEED,VMT,VHT,Q,TRAVEL_TIME,DELAY,NUM_SAMPLES,PCT_OBSERVED`. The selected station is filtered by `VDS_ID`. The website's Export Text report is tab-separated and has different units for occupancy; it is not configured as an automated source.

The [FTP terms](https://pems.dot.ca.gov/?directory=Help&dnode=Help&content=var_terms) distinguish the FTP account from the web account; the FTP account must be requested by email. [Caltrans lists PeMS.Support@dot.ca.gov](https://dot.ca.gov/programs/traffic-operations/mpr/pems-source) for PeMS questions. The terms permit an automated client that keeps a single connection and avoids repeated downloads of the same timestamp. The selected web account has been verified, but **FTP credentials, TLS support, directory listing, and real MQTT publication remain untested**. A website that uses FTP data must attribute PeMS.

The publisher defaults to the documented FTP file, validates it, and sends fully observed, recent 5-minute measurements to `traffic/pems/stations/<id>/5min` with QoS 1. The consumer writes those records into `traffic.traffic_5min`, which is the TimesNet source table. A missing station row, stale record, or incomplete measurement is rejected. Camera images are separate visual context, never model features.

The FTP `FLOW` unit is vehicles per 5 minutes and `OCCUPANCY` is a fraction from 0 to 1; `PCT_OBSERVED` is 0 to 100. The FTP filename supplies the timestamp, currently interpreted as California local time; verify that timezone against a real FTP sample before aligning forecasts. The website's 5-minute table displays occupancy as 0–100 percent, so divide that value by 100 if comparing it to the FTP record. The default hourly graph labels flow **Veh/Hour**, which must not be used as a 5-minute count.

An alternative approved source can be selected with `PEMS_SOURCE_MODE=https_csv`. Its `PEMS_SOURCE_URL` must return UTF-8 CSV with `station_id,timestamp,speed_mph,flow_veh_5min,occupancy_fraction,observed_percent`. Timestamps must be ISO 8601 (California local time, preferably with UTC offset) on 5-minute boundaries. `PEMS_HTTP_COOKIE` applies only to this source; keep it in the ignored `.env` file. The bridge does not scrape an undocumented PeMS endpoint.

1. Request separate PeMS FTP access for the real-time 5-minute feed, then put `PEMS_FTP_USER` and `PEMS_FTP_PASSWORD` in the ignored `.env`. The client defaults to explicit FTP over TLS (`PEMS_FTP_TLS=1`) to protect credentials. PeMS documentation does not confirm TLS support; verify it with the service. Setting `PEMS_FTP_TLS=0` uses plain FTP and exposes credentials in transit.
2. Set non-empty `CLICKHOUSE_USER` and `CLICKHOUSE_PASSWORD` in `.env`. The stock ClickHouse `default` account is restricted to localhost when no password is configured, so the MQTT consumer container cannot use it remotely.
3. Run `docker compose --profile live up -d clickhouse mqtt pems-publisher pems-consumer`. Check `docker compose --profile live logs -f pems-publisher pems-consumer` and query `SELECT max(ts), count() FROM traffic.traffic_5min FINAL` in ClickHouse. Verify a new timestamp every five minutes and compare a sample with PeMS.

`traffic.traffic_5min` contains one station only and has no station ID column. Select exactly one station for this run. The consumer's QoS 1 delivery plus ClickHouse `ReplacingMergeTree` supports duplicate retries, but its timestamp key would mix stations if two were ingested. No forecast or anomaly result is produced by these services: the separate TimesNet forecasting/inference service must subscribe to the MQTT topic or read the new ClickHouse rows and join them with its forecast on the same timestamp and units. The currently committed TimesNet model reconstructs historical windows; it cannot produce a week-ahead forecast.

For station selection, PeMS's observed percentage and detector health matter more than the mere presence of a map pin. Also verify that the CCTV image itself updates; the CWWP2 camera catalog reports camera status and location but does not certify a PeMS detector. Historical PeMS station data can train the model, while the live feed must provide the same quantity, units, aggregation and station ID.
